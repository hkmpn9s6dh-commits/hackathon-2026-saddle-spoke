# 08 — 旁白与成片：一条不靠耳朵的流水线

> 2026-11-13，赛道 H。第一版成片**没有旁白**，原因不是"本机不能 TTS"，而是三件小事叠在一起。
> 这一页把三件事、修法、以及可复用的四步流程写下来；下次开赛照这个做，不要再从零试。

## 0. 一句话原则

**画面跟着旁白走，不是旁白跟着画面走。**

先把台词合成完、量出每句多长，再让录屏按这个长度去演；最后混音时用的是**同一份数字**。
反过来做（先录屏、再配旁白）必然对不上，而且每改一句就要重录一遍。

## 1. 三条真实失败，与各自的修法

| 症状 | 真正的原因 | 修法 |
|---|---|---|
| 十句里只成一句，其余超时 | `edge-tts` 走的是 **WebSocket**（`wss://speech.platform.bing.com`），经代理时会在流中途被掐；一次成功会让人以为是"服务时好时坏" | 每句 **3 次退避重试 × 3 个声音**（Sonia → Ryan → Aria）。`scripts/narrate.py` 里就是这一层 |
| 系统语音合成调不动 | 本机安全策略**禁止 `Add-Type`**（运行期编译 .NET），所以 `System.Speech` 那条路整条不通；报错看起来像"没有 TTS" | 走 **COM**：`pywin32` 的 `SAPI.SpVoice` + `SAPI.SpFileStream`，不需要编译，不被挡。这就是离线兜底（本机英文只有 Zira） |
| 混出来有一段静音，但脚本没报错 | 合成失败仍会**留下一个 0 字节或全静音的文件**，后面的步骤只检查"文件存在" | 每句都验 **时长 ≥ 0.4 s** 且 **平均响度 ≥ −45 dB**（`ffmpeg volumedetect`）；不合格就当没合成，换下一个引擎 |

还有一条别人容易踩的：`ffmpeg` 得用**带 libx264 / aac 的构建**。Playwright 自带那个只有 VP9 与 PNG 编码器，
能录不能封。`imageio-ffmpeg` 的静态构建齐全，`pip install imageio-ffmpeg` 就有。

## 2. 四步流程

```bash
# 1) 台词（一句一行，短句；一句一个 id）
vim video/lines.json

# 2) 合成 + 逐句验收 → video/narration.json（含每句秒数）
python scripts/narrate.py
python scripts/narrate.py --check        # 只验不重做

# 3) 录屏：按旁白长度排时间表，动作卡在每句里 → video/timeline.json
node scripts/demo.mjs --url https://<线上地址>/

# 4) 混音：按同一份 timeline 摆每一句，垫极轻房间底噪，响度标准化，封 H.264/AAC
python scripts/mux.py
```

产物：`submission/<name>.mp4`。三个中间件（`narration.json` / `timeline.json` / `narration/`）都进 `.gitignore` 之外的
地方即可，片子本身由这三步重建。

## 3. 时间表是唯一真相

`demo.mjs` 里每个 beat 只有三件事：**说什么（id）、什么时候动手（`at`，秒）、额外留多久（`pad`）**。
每段的时长 = `LEAD(0.45) + 这句语音的长度 + PAD(0.8)`。

```js
{ id: 'trust', at: 2.4, act: 'allow' }        // 语音说到 2.4s 时点「Allow once」
{ id: 'stop',  at: 0.3, act: 'runchecks', pad: 2.4 }  // 自检要跑几秒，多留 2.4s
```

录完写 `video/timeline.json`（含 `preRollMs`：页面加载到开演之间的真实毫秒数）。`mux.py` 把每句放在
`preRoll + start + LEAD`，所以画面与声音不会漂。

**会漂的两种情况**，都在这里堵住了：

- 某个动作比这段旁白还慢（自检、跨域取 manifest）→ 给这段加 `pad`，别让它吃掉下一段。
- 录屏前有很长的加载 → `preRoll` 是实测的，不是估的；它被写进混音的偏移里。

## 4. 验收：不要靠耳朵

| 检查 | 命令 | 合格线 |
|---|---|---|
| 总时长 | `ffmpeg -i out.mp4` 的 `Duration` | 小于平台上限（本场 2:00），留 5–10 s 余量 |
| 整合响度 / 真峰 | `-af ebur128=peak=true` | **I ≈ −16 LUFS**（演讲主导）；TP ≤ −2 dBTP |
| 有没有空白段 | `-af silencedetect=n=-40dB:d=0.45` | 语音段与时间表对得上，误差 < 0.3 s |
| 每句真的在说 | 抽帧 + 看字幕是否与画面同一件事 | 逐段目视 |
| 台词本身 | 每句 ≤ 12 词、一句一个意思 | 听不清也读得懂（字幕同句） |

响度目标怎么定：纯演讲 -16 LUFS；带音乐的宣传片 -14；本片是"安静的演示片"，取 -16，
底噪压到 -34 dB 左右（`BED_GAIN=0.05` 再经 lowpass），只为了不让观众以为播放器坏了。

## 5. 下次开赛的清单

1. **开场前 10 分钟**先跑一次 `python scripts/narrate.py`，用一句 "one, two" 试通；不通就换 SAPI，别等到收工。
2. 台词**先写完**再录屏；一句一行，句子短。写完数一遍词数，按 2.6 词/秒估总长。
3. 录屏**不要**在时间表里写死"等 3 秒"，一律用旁白长度算。
4. 混音后**必跑**上面那张表，尤其 `silencedetect`：一段空白就能让评委以为视频坏了。
5. 成片与封面都在闸 D **过线之后**才做（规则 2）；改了画面就要重录，改了台词就要重混。

## 6. 这套东西的边界

- 声音是 **edge-tts 的 en-GB-SoniaNeural**（微软的在线神经语音），不是真人；语气平，但清楚、可懂、可字幕对齐。
- 兜底的 SAPI **只有 Zira（en-US）**，音色明显更旧；能用它出片，但不要拿它当默认。
- 本机没有第二个家族的模型可做"配音复核"；音色与节奏由我们自己的判断 + 上面那张表把关。
